Here’s a self-contained “spec pack” a coding agent can follow to fully rewrite/refactor your plotting system with **multi-trace 1D**, **spectrogram 2D**, **overlays/annotations**, and **60 FPS** as hard goals—while keeping the public API **simple** and the internals **maintainable**.

---

# 0) Goals & non-goals

**Goals**

* Simple, imperative public API (React optional).
* Multiple plots/traces per canvas; shared or independent axes.
* 1D lines/points (FFT, max-hold) + 2D spectrogram (streaming columns **and** full-image set).
* Consistent 60 FPS on typical modern hardware with multiple plots.
* Cursor, pan, zoom; clean overlays (markers, spans, tooltips).
* Deterministic, testable modules; low GC.

**Non-goals (initial)**

* WebGL requirement (keep CPU path; allow future GPU drop-in).
* Complex layout manager (start with a single plot viewport; allow multiple canvases or stacked panes later).

---

# 1) High-level architecture

**Layered engine (no React):**

* `Plot` orchestrates:

  * **Viewport** (world↔screen transforms, DPR/size)
  * **Scheduler** (RAF coalescing)
  * **Layers** (Line, Heatmap, Annotation)
  * **Input** (pointer/wheel → pan/zoom/cursor)
  * **Renderer entry** (calls each layer’s `draw`)

**React is a thin wrapper** (`usePlot`) that creates/destroys `Plot` and exposes the handle.

**Module boundaries**

* `engine/*`: orchestration, scheduling, viewport, Plot factory
* `layers/*`: drawing implementations (no DOM, no React)
* `math/*`: pure helpers (ticks, decimation, scales)
* `input/*`: translate DOM events → plot commands (pure-ish utilities)
* `color/*`: LUTs for heatmaps
* `theme/*`: all defaults
* `react/*`: wrapper only
* `types.ts`: public types/interfaces

# 3) Public API (stable, imperative)

```ts

// layers

const maxHold = plot.addLine({ id: 'max', color: '#f90' });

// data

// view

plot.setYRange([min,max]);

// lifecycle
plot.destroy();
```

# 4) Internal interfaces (key methods)

### `Plot.ts`

* `createPlot(canvas, options): PlotHandle`
* Keeps:

  * `Viewport` (xRange, yRange, width/height, dpr)
  * `Scheduler` (RAF debouncing)
  * `layers: Array<Layer>`
  * `resizeObserver`, listener registration
* Methods: `addLine`, `addHeatmap`, `addAnnotation`, `setXRange`, `setYRange`, `fit`, `requestDraw`, `destroy`
* Draw pipeline: clear → grid/axes (later) → each visible `Layer.draw(ctx, vp)`

### `Viewport.ts`

* Holds `[xMin,xMax]`, `[yMin,yMax]`, `width`, `height`, `dpr`
* Methods: `setRanges`, `setSize`, `sx(x)`, `sy(y)`

### `Scheduler.ts`

* `request()` coalesces draw calls into a single RAF
* `cancel()` on destroy

### `LineLayer.ts`

* State: `x: Float32Array`, `y: Float32Array`, `color`, `mode`
* Methods: `setXY`, `appendXY`, `draw(ctx, vp)`, `destroy()`
* Uses `decimateMinMax(x, y, vp.width, vp.xRange)`

### `HeatmapLayer.ts`

* Config: `width`, `height`, `colormap`
* State:

  * `rgba: Uint8ClampedArray` length `width * height * 4`
  * `head` (next column index), `readyCols` (0..width)
  * `lut = getColormapLUT(name)`
* Methods:

  * `pushColumn(bins: Float32Array|number[])`: write a column at `head`, `head = (head+1)%width`
  * `setFullImage(data: Float32Array|number[][], normalize?: boolean)`
  * `clear()`, `draw(ctx, vp)`, `destroy()`
* Render strategy:

  * Streaming: two `ImageData` segments split at `head`, `putImageData`, then scale `drawImage` to viewport
  * Full-image: directly create `ImageData` once and blit (cache result)

### `AnnotationLayer.ts`

* Simple drawables: vertical lines, spans, labels, points
* Public: `add/remove/updateAnnotation`
* Draw last (over lines/heatmap)

# 5) Math & formatting

### `decimate.ts`

* `decimateMinMax(x,y,pixelWidth,[xMin,xMax]) → Uint32Array`

  * Binary search to visible window
  * Bucket by pixel column; emit min & max indices (good faithfulness)
  * O(pixels) time; re-run when xRange or size changes

### `ticks.ts`

* `niceTicks([min,max], targetCount) → number[]`
* `formatTick(value) → string`
* Cache tick text when range & font unchanged

### `scales.ts`

* Linear/log mapping, `clamp`, `union`, percentage expansions
* Pixel snapping helpers (if needed to align crisp lines)

# 6) Input/interaction

### `pointer.ts`

* Given pointer events + modifiers → domain ops:

  * Drag → pan (translate x/y ranges)
  * (Optional) drag+modifier → box zoom
* No DOM calls here; pure calculations

### `wheel.ts`

* Wheel delta → zoom around cursor:

  * Compute cursor domain position
  * Apply symmetric zoom keeping cursor fixed
* Optional vertical wheel → y-pan if enabled

**Hooking into Plot**

* `Plot` registers DOM listeners and calls `pointer/wheel` helpers
* Apply results via `setXRange/setYRange`, then `requestDraw()`

# 7) Theme & rendering hygiene

* All defaults in `theme.ts` (background, line width, grid, fonts)
* Canvas DPR sizing:

  * On resize/DPR change only:

    * `canvas.width = clientWidth * dpr`, `canvas.height = clientHeight * dpr`
    * `ctx.setTransform(dpr,0,0,dpr,0,0)`
* Per-frame: avoid changing transform; just draw
* Zero allocations in hot paths (reuse arrays/paths where possible)

---

# 8) Performance rules (to hit 60 FPS)

* **RAF coalescing**: single scheduler per Plot
* **O(pixels) draw**: 1D uses min/max decimation; 2D uses LUT + column copy
* **Data structures**:

  * Typed arrays for data; no per-frame `new`
  * `ImageData` re-used where possible (beware cloning cost)
  * Optional `ImageBitmap` conversion (can help on some browsers)
* **Text**:

  * Cache `measureText` and formatted tick labels while ranges unchanged
* **DPR & resize**:

  * Size calcs only on resize/DPR change, not per frame
* **Optional off-main-thread** (future):

  * OffscreenCanvas + Worker for heatmap colorization
  * Transfer column buffers (transferables)

---

# 9) Maintainability guidance

* **Small files, single responsibility**; hard module boundaries
* **Public types in `types.ts` only**; JSDoc every public method
* **No React in engine/layers/math** (testable anywhere)
* **Consistent error handling**:

  * Throw on shape mismatches (e.g., wrong heatmap size)
  * Guard nulls at API boundary, not deep inside
* **Config flags** for optional features:

  * `interactions: { boxSelect?: boolean, yWheelPan?: boolean }`
  * `debug: { overlay?: boolean }`
* **Avoid “god state”**: layers own their data; Plot owns viewport/scheduler
* **Extensibility**: adding a new `Layer` should not touch `Plot` (beyond `addXxx` factory)

# 1) Core engine

## 1.1 `Viewport`

Purpose: world↔screen transforms, ranges, DPR/size.

```ts
export class Viewport {
  // CSS pixels (not device pixels)
  width: number;  // e.g., clientWidth
  height: number; // e.g., clientHeight
  dpr: number;    // devicePixelRatio

  x: [number, number];
  y: [number, number];

  constructor(x: [number, number], y: [number, number], width = 300, height = 150, dpr = 1);

  setRanges(x: [number, number], y: [number, number]): void;
  setSize(width: number, height: number, dpr: number): void;

  // world → screen (CSS pixels)
  sx(x: number): number;
  sy(y: number): number;

  // screen → world
  ix(px: number): number;
  iy(py: number): number;

  // visible domain extents, cached computation
  xSpan(): number; // x[1] - x[0]
  ySpan(): number;
}
```

**Notes**

* All transforms are in CSS pixels; the engine sets `ctx.setTransform(dpr,0,0,dpr,0,0)` once after resize.
* No allocations in hot paths.
* `ix/iy` are used by input handlers (cursor, zoom-around-cursor).

RAF coalescer.

```ts
export class Scheduler {

  cancel(): void;  // cancel any pending RAF
```

**Notes**

## 1.3 `Plot`

Thin orchestrator; owns canvas, context, layers, viewport, scheduler.

```ts
export interface PlotOptions {
  dpr?: number;

  interactions?: { boxSelect?: boolean; yWheelPan?: boolean };
```

**Internal responsibilities**

* Maintain `layers: Layer[]` where `Layer` has `id`, `visible`, `draw(ctx, vp)`, `destroy()`, and optional `getExtents(): { x?: [number,number]; y?: [number,number] }`.
* `ResizeObserver`: recompute canvas backing store (`canvas.width/height`) and `ctx.setTransform`, then `requestDraw()`.
* Clear frame: one background fill per frame. Grid/axes can be separate layers or an internal prepass.

## 2.1 `LineLayer` (1D)

For FFT plots, overlays (max-hold), etc.

```ts
export type LineMode = 'line' | 'points';

export interface LineConfig {
  id: string;
  color?: string;         // default theme color
  mode?: LineMode;        // 'line' (default)
  lineWidth?: number;     // optional override
}

export class LineLayer implements Layer {
  readonly id: string;
  visible = true;

  constructor(cfg: LineConfig, onDirty: () => void);

  setXY(x: Float32Array | number[], y: Float32Array | number[]): void;
  appendXY(x: Float32Array | number[], y: Float32Array | number[]): void; // O(n) copy; caller decides frequency
  setColor(c: string): void;
  setMode(m: LineMode): void;

  draw(ctx: CanvasRenderingContext2D, vp: Viewport): void;
  destroy(): void;

  getExtents(): { x: [number, number]; y: [number, number] };
}
```

**Implementation details**

* Internal storage: `x: Float32Array`, `y: Float32Array`. Convert `number[]` once at boundary.
* **Decimation:** Use `decimateMinMax(x, y, vp.width, vp.x)`; return indices in draw order.
* **Complexity:** O(pixels) per frame, not O(n).
* **GC:** No allocations in `draw` except a reusable index buffer. Pre-allocate index array to `2*vp.width` and reuse.
* **Extents:** Cache min/max on `setXY/appendXY`.

## 2.2 `HeatmapLayer` (2D / spectrogram)

Column streaming + full image set. RGBA backing store for fast blits.

```ts
export interface HeatmapConfig {
  id: string;
  width: number;    // columns (time)
  height: number;   // rows (freq bins)
  colormap?: string; // 'plasma' default
  clip?: { min: number; max: number } | 'auto'; // normalization range
}

export class HeatmapLayer implements Layer {
  readonly id: string;
  visible = true;

  constructor(cfg: HeatmapConfig, onDirty: () => void);

  pushColumn(bins: Float32Array | number[]): void;             // length == height
  setFullImage(data: Float32Array | number[][], normalize?: boolean): void;

  setColormap(name: string): void;         // updates LUT
  setClip(clip: HeatmapConfig['clip']): void;

  clear(): void;

  draw(ctx: CanvasRenderingContext2D, vp: Viewport): void;
  destroy(): void;

  // Optional (for fit() if spec wants to influence y-range)
  getExtents(): { y: [number, number] };
}
```

**Implementation details**

* **Storage**: `rgba = new Uint8ClampedArray(width * height * 4)` (column-major or row-major—pick one and stick to it).
* **Streaming**: Maintain `head` column index; on `pushColumn`, write RGBA for that column using a **precomputed LUT**.
* **LUT**: `Uint8Array(256*4)` from `color/colormap.ts`.
* **Normalization/Clip**:

  * If `clip:'auto'`, track running min/max or an EMA of min/max to avoid spikes.
  * Provide `setClip({min,max})` to lock normalization.
  * Mapping: `vNorm = clamp((v-min)/(max-min), 0, 1); idx = (vNorm*255)|0`.
* **Draw**:

  * **Streaming:** Split at `head` and `putImageData` two segments (right then left), then scale once using `drawImage` to viewport rect (disable smoothing).
  * **Full image:** fill entire `rgba` and `putImageData` once; cache any immutable `ImageData` if your browser perf benefits.
* **Complexity**:

  * `pushColumn`: O(height) + LUT lookup.
  * `draw`: `putImageData` (two segments) + one `drawImage` to scale.

**Memory notes**

* RGBA buffer = `width * height * 4` bytes. 2048×1024 ≈ 8 MB—fine.

## 2.3 `AnnotationLayer`

Draw simple overlays last.

```ts

export interface AnnotationBase { id: string; type: AnnotationType; visible?: boolean; z?: number; }
export interface VLine extends AnnotationBase { type: 'vline'; x: number; color?: string; lineWidth?: number; }
export interface HLine extends AnnotationBase { type: 'hline'; y: number; color?: string; lineWidth?: number; }
export interface Span  extends AnnotationBase { type: 'span'; x0: number; x1: number; color?: string; alpha?: number; }
export interface Label extends AnnotationBase { type: 'label'; x: number; y: number; text: string; color?: string; bg?: string; }
export interface Point extends AnnotationBase { type: 'point'; x: number; y: number; radius?: number; color?: string; }

export interface AnnotationConfig extends Annotation {}

export class AnnotationLayer implements Layer {
```

**Notes**

* Keep it simple and stateless: data is a small array; sort by `z` each draw if needed (or maintain a min-heap keyed by z if lots of edits).

# 3) Math & utility modules

## 3.1 `decimate.ts` (1D decimator)

```ts
export function decimateMinMax(
  x: Float32Array, y: Float32Array, pixelWidth: number, xrange: [number, number],
  reusableOut?: Uint32Array // optional: caller supplies buffer of length >= 2*pixelWidth
```

**Behavior**

* Binary-search `x` to visible [xa, xb] window.
* Bucket points by screen column, compute min & max y per bucket.
* Emit indices `[iMin, iMax, ...]` in draw order; if min==max, emit once.
* **O(pixels)** time, **O(pixels)** memory.

# 7) Dirty-state & draw contract

* **Plot** maintains a single `requestDraw()` method; layers call the `onDirty` callback they receive in constructor to trigger a redraw.
* **Never** draw directly from data setters; always call `onDirty()` then the coalesced draw happens on next RAF.
* **Resize/DPR**: only recalculates canvas backing store and transform, then `requestDraw()`.

---

# 8) Error handling & invariants

* `LineLayer.setXY/appendXY`: `x.length === y.length` or throw.
* `HeatmapLayer.pushColumn`: `bins.length === height` or throw.
* `HeatmapLayer.setFullImage`: length must equal `width*height` (or nested `[height][width]`) or throw.
* `Viewport` ranges: guard zero-span (expand by tiny epsilon).

---

# 9) Performance budgets & complexity

* `LineLayer.draw`: O(pixels) per frame; no allocations (reused index buffer).
* `HeatmapLayer.pushColumn`: O(height) per column; LUT lookup; zero extra allocations.
* `HeatmapLayer.draw`: 1–2 `putImageData` + 1 `drawImage`; avoid per-frame `new ImageData` by reusing where possible (browser-dependent—measure).
* `Scheduler`: ≤ 1 RAF pending; frame time target ~2–4 ms for multi-layer scenes.

## Rendering & performance

1. **No 1D decimation (draws every point)**

* **Problem:** The 1D path walks all samples and draws line segments for each. Large arrays + multiple traces = dropped frames.
* **Fix:** Add an O(pixels) decimator (min/max per pixel column) and reuse a preallocated `Uint32Array` of length `2 * width`. Recompute only when x-range or width changes.

2. **Heatmap builds a full device-sized `ImageData`**

* **Problem:** Each draw builds / fills an RGBA buffer at device resolution and `putImageData`s it. That’s expensive and CPU-bound.
* **Fix:** Store heatmap in source resolution and **scale with `drawImage`** to viewport (GPU path). For streaming, maintain a **column ring buffer** in RGBA and only update the new column(s); then composite with **two blits** (split at head) + a single `drawImage`. Disable smoothing for crisp pixels.

3. **Global `imageSmoothingEnabled = true`**

* **Problem:** Good for lines; **bad for heatmaps** (blurry + slower resampling).
* **Fix:** For heatmap draw, `save()`, `imageSmoothingEnabled = false`, `drawImage`, then `restore()`; leave the default for lines.

4. **No `ResizeObserver` / DPR-change trigger**

* **Problem:** Canvas backing store is sized during draw; if the element resizes (or DPR changes) without other interactions, the canvas can stay stale.
* **Fix:** Add a `ResizeObserver` on the canvas (or container) and a **DPR change listener** (`matchMedia` or timer check) to call a tiny `resizeToElement()` that updates `canvas.width/height` and `ctx.setTransform(dpr,0,0,dpr,0,0)`, then `requestDraw()`.

5. **Per-frame `getBoundingClientRect`**

* **Observation:** You call it inside render. It’s okay if you render rarely, but it’s measurable at 60 FPS.
* **Fix:** Cache rect in `ResizeObserver` and in pointer events; during steady animation, avoid calling it every frame.

6. **Text/tick cost not cached**

* **Problem:** If ticks/labels are measured or formatted every draw, text layout becomes a hidden perf sink.
* **Fix:** Cache tick positions + formatted strings keyed by `(range, font, targetCount)`. Only recompute when range or font changes.

7. **Area fill under line always on**

* **Problem:** The line path ends by adding a baseline, closing, and filling, which can be costly and not always desired.
* **Fix:** Gate fill under line behind a config flag; set default to off for performance unless explicitly enabled.

# Axes: Implementation Summary

## Purpose

Provide reusable axis math + rendering that:

* Works for **bottom/top/left/right** axes
* Supports **linear/log/time** scales
* Draws **grid lines** (behind data) and **axis lines/ticks/labels** (in front)
* Is **fast**, **cache-friendly**, and **testable**

---

## Design Pattern (pick one)

**Recommended (A): Two regular layers**

* `GridLayer` (zIndex: -500) — draws grid using ticks from models.
* `AxisLabelLayer` (zIndex: +500) — draws axis lines, tick marks, tick labels, titles.
* Both layers consume the same `AxisModel`(s).

**Alternative (B): Phased rendering**

* Add `phase` to Layer: `'background' | 'grid' | 'content' | 'foreground' | 'cursor' | 'debug'`.
* Engine draws phases in fixed order. Axis grid in `grid`, labels in `foreground`.

**Simplest (C): Hard-wired passes**

* Call `drawGridFromAxes` before data; `drawAxisLabels` after data (not pluggable).

> A or B keeps axes pluggable and predictable. A is simplest to drop in now.

## AxisModel (pure math, cached)

**Responsibilities**

* Holds `range`, `spanPx` (axis length in CSS px), `side`, `scale`.
* Computes **nice ticks** and **formatted labels**.
* Caches results keyed by `(range, spanPx, scale, ticksTarget, formatter presence)`.

**API**

```ts
export interface Tick { value: number; label: string; px: number; }

export class AxisModel {
  constructor(opts: AxisOptions);
  setRange(r: Range): void;
  setSpanPx(px: number): void;            // axis length in CSS px
  ticks(): Tick[];                         // cached; recompute only on key change
}
```

**Notes**

* `px` is **CSS** px (engine sets `ctx.setTransform(dpr,0,0,dpr,0,0)` once).
* For Y axes, compute `px` with inverted mapping (canvas Y grows downward).
* Implement `niceTicksLinear`, `niceTicksLog`, `niceTicksTime`, and default `formatEng`/`formatTime`.
* Keep this file **pure** and fully unit-tested.

## AxisLayer (canvas)

**Responsibilities**

* Draw **grid** (optional).
* Draw **axis line**, **tick marks**, **tick labels**, **axis title**.
* Use **device-pixel snapping** for crisp 1px strokes.

**API**

```ts
export class AxisLayer {
  constructor(opts: AxisOptions, theme: AxisTheme);
  setRange(r: Range): void;       // forward to model
  setSpanPx(px: number): void;    // forward to model
  setTheme(t: AxisTheme): void;
  draw(ctx: CanvasRenderingContext2D, vp: Viewport): void;
}
```

**Drawing rules**

* **Grid**: draw first (behind data). For bottom/top use vertical lines at `tick.px`; for left/right use horizontal lines.
* **Axis line + ticks**: snap to device pixel (`Math.round(px) + 0.5`) for crispness.
* **Labels**: cache `measureText` or avoid measuring unless necessary; place with small paddings from `AxisTheme`.
* Keep `imageSmoothingEnabled` default (only disable when scaling images, not for vector lines/text).

---

## Engine Wiring

* Create one `AxisModel` per side you need (typically `bottom` and `left`).
* On **resize**:

  * `axisBottom.setSpanPx(vp.width)`
  * `axisLeft.setSpanPx(vp.height)`
* On **range change**:

  * `axisBottom.setRange(vp.x)`
  * `axisLeft.setRange(vp.y)`
* **Draw order**:

  * Background
  * **GridLayer** (or `AxisLayer` drawing just grid)
  * Data layers (Line, Heatmap, etc.)
  * **Axis labels/ticks** (second AxisLayer or same instance in foreground)
  * Cursor/hover/annotations
  * Debug

If using option A, you can implement `GridLayer` and `AxisLabelLayer` as two tiny wrappers around the same `AxisModel`(s), differing only in what they draw and their `zIndex`.

## Interaction Coupling

* Pan/zoom modifies `vp.x/vp.y` → call `setRange` on corresponding `AxisModel` → `ticks()` cache invalidates automatically → next draw reflects updated ticks/labels.
* For **log**/**time** scales, keep pan/zoom math in domain; `AxisModel` handles display formatting.

---

## Performance Checklist

* `AxisModel.ticks()` is cached; recompute only when `(range/span/scale/target/formatter)` changes.
* Avoid per-frame `measureText`; cache label widths if label text is stable.
* Use **device-pixel snapping** for crisp lines: `Math.round(px) + 0.5`.
* Don’t call `getBoundingClientRect` during draw; rely on `ResizeObserver` updates from the engine.

  * Y-axis inversion mapping
